# 全局扩展管理

入口：**设置 → 扩展**。操作的是当前连接的 backend，不是前端所在机器，也不修改 pi CLI 的配置。

## 功能与生效

- 内置功能扩展只能启停；权限门、沙箱、diff 持久化和 MCP GUI 桥接不在可操作列表里。
- 全局安装的用户扩展可以启停或“从 Argon 移除”。不提供项目或会话级开关。
- 开关表示允许加载，不等于工具已对模型开放。模型策略、工具预设、MCP 服务器开关仍然独立生效。
- 保存后，空闲会话自动重载；运行中的会话等整个任务结束（含重试、压缩和自动续跑）后重载。无需重启 backend。
- 页面显示尚未完成重载的会话数量。失败时可以点“重载 / 重试”；具体扩展加载错误仍在各对话的问题面板里显示。
- “刷新列表”只重新发现资源，不加载扩展、不下载安装缺失的软件包。项目独有扩展不出现在全局安装列表里。

## 移除不等于卸载软件包

确认后，扩展从列表隐藏，并持久禁止加载。**不会删除源文件、运行包卸载脚本，或删除包内其他扩展、技能和提示词。**

这是有意采用的安全边界：一个软件包可能包含多个共享资源，外部路径也可能指向用户正在开发的代码。卸载整个软件包和磁盘清理不在此版本范围内。

如果要恢复被移除的条目，关闭 Argon 后编辑 backend 的 `$ARGON_HOME/agent/extension-policy.json`，删除对应 ID 的记录，再启动 Argon。也可以在确认没有并发修改配置时编辑后点击“重载 / 重试”。

## 配置与优先级

`extension-policy.json` 保存 Argon 的全局覆盖；没有覆盖的资源沿用 pi 原来的选择。

- 内置扩展用 `builtin:<name>` 标识。
- npm 包扩展用不含版本的包来源和包内相对路径标识，同一包在项目中的安装也遵守全局覆盖。
- git/HTTP 包用来源字符串和包内相对路径标识（改变来源或 ref 后视为另一来源）。
- 本地扩展用绝对路径标识；移动或复制文件会得到新条目。

全局覆盖在扩展代码导入之前执行，包含项目信任 bootstrap 阶段。它不会允许未信任项目的资源被发现，也不会影响宿主 inline extension。扩展开关不是对恶意代码的安全隔离：已允许的第三方扩展仍拥有 backend 用户的权限。
